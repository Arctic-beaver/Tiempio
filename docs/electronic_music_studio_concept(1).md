# User-Friendly Electronic Music Studio — Product Concept

## Основная идея

Создать красивое, понятное desktop-приложение для создания электронной музыки с нуля.

> **Пользователь хочет делать музыку, а не сначала изучать DAW.**

Продукт должен позволять человеку без опыта в профессиональных DAW открыть приложение и практически сразу начать создавать полноценный электронный трек.

Это не «детская DAW», не AI-генератор и не просто урезанный Ableton. Цель — сохранить достаточную музыкальную глубину, но убрать ненужную сложность взаимодействия, технические ловушки и высокий порог входа.

Типичный первый workflow:

> создать MIDI → выбрать инструмент → сыграть → опустить бас на октаву → залупить мелодию с паузой → добавить drums → временно заглушить другую дорожку → изменить громкость → добавить новую MIDI-дорожку.

Ни одно из этих действий не должно требовать отдельного tutorial.

## Позиционирование

Продукт специализируется на **электронной музыке**.

Все основные встроенные звуки синтезируются самим приложением. Мы сознательно не пытаемся поставлять реалистичные рояли, гитары, оркестровые инструменты или огромные sampled-библиотеки.

Пользователь при желании может импортировать собственное аудио.

## Звуковая стратегия

Вместо огромной библиотеки семплов используются три системы:

1. **Synth Engine**
2. **Drum Synth**
3. **MIDI / Pattern Library**

> **Не давать человеку тысячу вариантов там, где ему нужны десять хороших.**

## 1. Synth Engine

Synthesizer самостоятельно генерирует звук математически вместо проигрывания заранее записанного аудиофайла.

Один synth engine может создавать:

- Bass
- Lead
- Pad
- Pluck
- Keys
- Atmosphere
- Drone
- Experimental sounds

Пользователь не обязан понимать oscillator, filter cutoff, resonance, envelope, LFO, ADSR и другие технические параметры.

Вместо этого:

### Bass

- **Deep** — низкий и массивный
- **Punchy** — короткий и ритмичный
- **Warm** — мягкий и округлый
- **Soft** — спокойный
- **Dirty** — агрессивный
- **Retro** — характерный синтовый

После выбора:

- Darker ↔ Brighter
- Softer ↔ Harder
- Clean ↔ Dirty
- Short ↔ Long
- Narrow ↔ Wide

Внутри эти controls могут управлять сразу несколькими DSP-параметрами.

Позже может появиться **Advanced Mode**, раскрывающий настоящий synth interface.

## 2. Presets

Preset — сохранённая конфигурация synth engine.

Например, **Warm Bass** внутри представляет конкретный набор oscillator/filter/envelope/effects parameters.

Пользователь видит:

> Bass → Warm

и сразу получает рабочий инструмент.

Вместо сотен почти одинаковых presets нужна маленькая curated-библиотека действительно качественных и заметно отличающихся звуков.

## 3. Procedural Generation

Procedural generation используется прежде всего как **внутренний инструмент производства звуков**.

Система генерирует множество допустимых конфигураций synth/drum engine.

Например:

> Generate 500 bass variants.

Затем человек:

1. прослушивает варианты;
2. выбирает лучшие;
3. дорабатывает их;
4. присваивает понятные названия;
5. добавляет в продукт только лучшие варианты.

> **Машина генерирует много → человек отбирает и полирует лучшее → пользователь получает маленькую качественную палитру.**

Procedural generation не обязательно показывать пользователю.

## 4. Drum Synth

Electronic drums также генерируются самим приложением:

- Kick
- Snare
- Clap
- Closed Hi-Hat
- Open Hi-Hat
- Toms
- Electronic Percussion
- Clicks
- Noise / Transition FX

Пользователь не выбирает `Kick_384.wav`.

Вместо этого:

### Kick

- Deep
- Punchy
- Soft
- Hard
- Clean
- Dirty

Настройки могут выглядеть как:

- Deep ↔ Tight
- Soft ↔ Hard
- Clean ↔ Dirty
- Short ↔ Long

Внутри они управляют реальными параметрами drum synthesizer.

## 5. MIDI / Pattern Library

Большая часть музыкального контента существует не как audio loops, а как редактируемые MIDI patterns:

- drum grooves;
- bass rhythms;
- chord patterns;
- arpeggios;
- melodic starting points.

Например:

**Pattern:** Straight / Funky / Sparse / Driving / Broken

**Sound:** Soft / Punchy / Dark / Clean / Lo-Fi

**Complexity:** Simple ↔ Busy

Один MIDI pattern можно применять к множеству synth/drum sounds, создавая большое пространство комбинаций без гигантской библиотеки файлов.

## 6. Project Storage

Проект по возможности хранит параметры синтеза, а не отрендеренные WAV-файлы встроенных инструментов.

Пример:

```text
Bass
Preset: Warm
Brightness: 35
Attack: Soft
Width: 20
Character: Analog
```

Для drums:

```text
Kick
Type: Deep
Punch: 63
Body: 78
Tail: 31
Character: Clean
```

Audio генерируется во время playback, а при экспорте рендерится в обычный audio format.

Преимущества:

- маленькие project files;
- полная редактируемость;
- огромное количество вариаций;
- отсутствие огромной sample library.

## 7. User Audio Import

Пользователь может выбрать:

> **+ Add your sound**

И перетащить собственный audio file.

Приложение может предложить определить роль:

- Vocal
- Drums
- Bass
- Melody
- Other

Базовые операции:

- move;
- cut;
- loop;
- mute;
- volume;
- fade;
- потенциально pitch;
- потенциально tempo/time stretching.

В будущем может появиться **Turn into instrument**, превращающий пользовательский sample в playable instrument. Для текущего MVP это необязательно.

# UX Philosophy

> **Программа должна объяснять себя интерфейсом.**

Если действие можно однозначно вывести из намерения пользователя, нельзя заставлять его понимать техническую реализацию.

### Пользователь хочет бас ниже

Показываем:

> Octave ↓ / Octave ↑

Не заставляем сначала узнавать про транспонирование на 12 semitones.

### Пользователь добавляет Bass

Приложение автоматически:

- создаёт рабочий instrument;
- подключает его;
- открывает piano roll;
- показывает подходящий диапазон;
- гарантирует, что нажатие клавиши производит звук.

### Пользователь добавляет Drums

Сразу появляется рабочий drum instrument и понятная rhythm grid. Никакой дополнительной настройки routing.

### MIDI приходит, но звука нет

Приложение диагностирует причину вместо молчаливого неработающего состояния.

Например:

> MIDI signal received, but this track has no instrument. Choose one?


# System Audio Coexistence

Пользователь должен иметь возможность слушать референсы в браузере, Spotify, YouTube или другом приложении одновременно с работой в Tiempio.

> **Tiempio не должен по умолчанию забирать аудиоустройство в эксклюзивное пользование и заставлять закрывать другие приложения.**

## Базовое поведение

- приложение запускается в **Shared Audio Mode**;
- звук Tiempio воспроизводится параллельно с системным звуком других приложений;
- пользователю не нужно вручную разбираться в драйверах, output routing или exclusive mode;
- смена наушников или аудиоустройства не должна требовать перезапуска проекта;
- при конфликте приложение диагностирует причину и предлагает понятное исправление, а не просто перестаёт звучать.

## Low-Latency Mode

Для записи с минимальной задержкой в будущем может существовать отдельный **Low-Latency Mode**. Он не включается автоматически.

Перед включением приложение ясно объясняет:

- зачем нужен этот режим;
- что он может ограничить воспроизведение звука в других приложениях;
- как вернуться к Shared Audio Mode.

## UX-индикатор

В верхней панели может находиться компактный статус:

> **Shared audio**

По нажатию он показывает текущее поведение без необходимости открывать технические настройки.

## Критерий качества

Пользователь должен иметь возможность:

1. открыть референс в браузере или музыкальном приложении;
2. не закрывая его, вернуться в Tiempio;
3. проиграть собственный проект;
4. сравнивать звучание двух источников без перенастройки аудиосистемы.

Это является не дополнительной функцией, а частью базового обещания продукта: **приложение не должно создавать технические препятствия между музыкальным намерением и действием пользователя.**


## Reference Track Mode — позже

Пользователь может импортировать композицию как отдельную reference-дорожку. Она быстро включается и выключается для сравнения, не попадает в финальный export и визуально отделена от музыкальных слоёв проекта. Это дополняет, но не заменяет системный Shared Audio Mode.

# Harmony & Music Theory Guidance

Piano roll одновременно является инструментом и помощником.

Потенциально показываются:

- текущая тональность;
- ноты гаммы;
- chord tones;
- harmonic relationships;
- подходящие bass notes;
- потенциально конфликтующие ноты;
- chord progression suggestions;
- разумные octave ranges.

Цель — не сделать музыку вместо пользователя.

> **Помочь человеку самостоятельно делать музыку и постепенно понимать, почему она звучит именно так.**

# Progressive Disclosure

Низкий порог входа не должен означать низкий потолок.

### Beginner

- понятные presets;
- музыкальные controls;
- автоматические defaults;
- минимум технических терминов.

### Customize

- больше параметров;
- точное редактирование;
- дополнительные effects;
- расширенная работа с MIDI.

### Advanced

В будущем:

- настоящие synth parameters;
- сложная automation;
- дополнительные routing/mixing possibilities;
- профессиональные controls там, где они действительно нужны.

# Sound Library Philosophy

Продукт сознательно отказывается от подхода:

> «У нас 50 000 sounds».

Вместо сотен почти одинаковых bass presets:

- Deep
- Warm
- Punchy
- Soft
- Dirty
- Retro

Вместо тысячи kicks — несколько характерных, качественных вариантов, каждый из которых легко отличить на слух и дополнительно настроить.

Возможное продуктовое сообщение:

> **No 10,000 sounds. Just good ones.**

# Что мы сознательно НЕ делаем

На первоначальном этапе:

- реалистичные sampled acoustic instruments;
- огромную sample library;
- попытку покрыть все музыкальные жанры;
- оркестровые библиотеки;
- тысячи presets;
- зависимость от сторонних generative-AI services для встроенных sounds;
- сложный professional routing как обязательную часть workflow;
- интерфейс, построенный вокруг технической архитектуры audio engine.

# Основное продуктовое обещание

> **Красивый и понятный инструмент для создания электронной музыки, который можно открыть впервые и начать писать трек, не изучая сначала саму программу.**

Приложение должно быть достаточно простым, чтобы новичок получил удовольствие в первый час, и достаточно глубоким, чтобы после освоения базовых действий ему всё ещё было интересно создавать собственную музыку.

## Главный принцип

> **Не давать человеку тысячу возможностей выбора там, где ему нужны десять хороших.**
